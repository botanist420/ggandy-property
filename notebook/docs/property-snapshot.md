# 物件資料快照：從 Google Sheet 在正式機重建物件

把一個物件「截至目前」的資料（聯絡人、物件、出租單位、租約、租金期次）匯出到 Google Sheet，再到另一個資料庫（正式機）用 Odoo shell 原樣重建。物件編號、租約編號由正式機自己取號；其餘資料逐欄對齊 Sheet。

| 老闆原始帳單（對帳來源） | `1UEq3nR6oCoty68HlVGhsPuJU_ehxO8Fmv9JI7S4K8E4`「羅斯福路公館整合」分頁 |

## 1. Sheet 格式

一個分頁分成幾段：`【段落名稱】` 一列、欄位名稱一列、資料列，段落之間空一列。段落前面的說明列會被忽略。

| 段落 | 一列代表 | 重點欄位 |
| --- | --- | --- |
| 【聯絡人】 | 一位房東或房客 | 名稱、身分（房東／房客）、電話、Email、內部參考、備註 |
| 【物件】 | 物件（只有一列） | 物件名稱、物件類型、管理模式、房東（對應聯絡人名稱）、負責人（使用者名稱或登入帳號）、地址、國家（ISO 代碼，例如 `TW`） |
| 【出租單位】 | 一間房 | 房號、月租、押金月數、水電計費方式／單價／固定金額；「狀態（核對用）」只拿來核對 |
| 【租約】 | 一份租約 | 房號、房客、起訖日、月租、押金、繳租日、入住水電錶度數、狀態（生效中／草稿） |
| 【租金期次】 | 一間房的一個月 | 租金、管理費、水電設定、上期／本期度數、備註；`（核對用）` 欄位是系統應算出的用量、金額與應收合計 |
| 【對帳：老闆原始帳單 vs ERP】 | 一間房的一個月 | 純紀錄，插入腳本不讀 |

- 選單欄位用畫面上的中文選項（例如「依度數計費」「每月固定金額」「生效中」），腳本會轉成系統代碼。
- 數字可以有千分位逗號；日期可用 `2026-05-01` 或 `2026/5/1`。
- 「本期度數」留空＝還沒抄表；填 `0` 也一樣當作沒抄。
- 其他數字欄位留空會被當成 `0`。匯出時一律寫出 `0`，方便看出是刻意的（例如 8 月起固定水費 `0`）。

把 CSV 放進 Sheet：Google Sheet → 檔案 → 匯入 → 上傳 → 「取代目前的工作表」，並**取消勾選「將文字轉換成數字、日期和公式」**。電話開頭的 `+` 才不會被當成公式。

## 2. 插入腳本做什麼

依序：

1. **聯絡人**：先用電話（只比數字）找，再用名稱找。找到一筆就沿用，名稱、電話、Email、內部參考和 Sheet 不同就改成 Sheet 的值（Sheet 留空的欄位不清掉），並加上身分旗標；找到多筆就停下；都沒有就新增。
2. **物件**：國家用代碼找，縣市、行政區用中文名稱找，負責人用使用者名稱或登入帳號找；找不到就留空並印警告。
3. **出租單位**：照 Sheet 建立，含水電設定。
4. **租約**：建立草稿 → `_generate_rent_schedule()` 依租期產生期次。產生的期次月份必須和 Sheet 完全一致，否則停下。
5. **租金期次**：由舊到新逐期寫入 Sheet 的租金、水電設定、度數、備註（會覆蓋單位帶入的預設值，例如單月免收水費）。
6. **生效**：Sheet 狀態是「生效中」的租約改成生效，並刷新單位狀態。**不呼叫** `action_activate()`，因為它會呼叫全域的 `_cron_create_due_invoices()`，順便替其他物件建帳單。
7. **草稿帳單**：替這個物件起租日到今天的期次建草稿租金帳單（和租約生效時一樣）。加 `CREATE_INVOICES=0` 可以跳過。
8. **逐欄核對**：重新讀出所有欄位，和 Sheet 比對（含用量、金額、應收合計，以及草稿帳單金額）。

只要有任何差異就 rollback。`COMMIT=1` 也一樣：一定要「差異 0」才會寫入。

不會做：整備專案、庫存位置（需要的話到物件按「開始整備」）、房東合約、帳單過帳與收款、附件。

## 3. 在正式機執行（給 Claude 的步驟）

**原則：以 Google Sheet 為準。** 正式機上可能已經有使用者手動建立的同名物件與資料，那些都是舊資料，不要拿來和 Sheet 合併。

### 3.1 準備

1. 確認 Odoo 容器名稱與資料庫名稱（`docker ps`、odoo.conf），以及容器內的 `$HOST` 等環境變數。下面以 `<容器>`、`<資料庫>` 表示。
2. 取得最新程式（`git pull`）。正式機的模組版本必須和本機一致（`ggandy_property_management` 等模組已升級到最新），且已安裝 `l10n_tw`（建草稿帳單要用 `sale` 日記帳）。
3. 確認正式機連得到 Sheet：`curl -sL '<SHEET_URL>' | head -3`，要看到 `大安公館 資料快照` 開頭；看到 HTML 代表 Sheet 沒有公開。

### 3.2 盤點並處理正式機上的舊資料

4. 盤點（只讀）：

   ```bash
   docker exec -i -e PROPERTY_NAME=大安公館 <容器> sh -c 'odoo shell -c /etc/odoo/odoo.conf -d <資料庫> \
     --db_host="$HOST" --db_port="$PORT" --db_user="$POSTGRES_USER" --db_password="$POSTGRES_PASSWORD" \
     --no-http --log-level=error' < notebook/scripts/inspect_property_data.py
   ```

5. 把盤點結果整理給使用者，並提出處理方式，**等使用者確認後才動手**：
   - **建議：改名封存**（不刪資料，最安全）
     - 舊物件改名為「大安公館（舊-YYYYMMDD）」，物件與單位都封存（`active=False`）。
     - 舊的生效中租約：沒有已過帳帳單的用 `action_cancel()`，有的話用 `action_terminate()`，避免排程繼續替舊租約建帳單。
     - 舊租約的草稿帳單刪除；已過帳帳單和收款不動。
   - **完全刪除**：只有使用者確認舊資料全是測試資料時才做。先用 `notebook/scripts/reset_property_tenants.py`（`PROPERTY_CODE=<舊物件編號>`，先試跑再 `COMMIT=1`）刪掉租約、期次、帳單、收款。它只會刪名稱以 `demo-` 開頭的房客，其他聯絡人要另外確認。接著刪單位與物件；被整備專案、庫存位置等引用而刪不掉的，就改用封存。
   - 處理完要確認：沒有任何使用中的物件**名稱剛好等於**「大安公館」（插入腳本用完全相同的名稱判斷是否重複）。
6. 舊的聯絡人不用先處理：插入腳本會先用電話、再用名稱找既有聯絡人並沿用，名稱、電話、Email 和 Sheet 不同時會**改成 Sheet 的值**並印出警告。同一支電話或名稱找到多筆時會停下，請使用者決定要保留哪一筆。

### 3.3 插入

7. **試跑**（不寫入、不取正式編號）：

   ```bash
   docker exec -i <容器> sh -c 'odoo shell -c /etc/odoo/odoo.conf -d <資料庫> \
     --db_host="$HOST" --db_port="$PORT" --db_user="$POSTGRES_USER" --db_password="$POSTGRES_PASSWORD" \
     --no-http --log-level=error' < notebook/scripts/import_property_snapshot.py
   ```

8. 看輸出：
   - `核對差異 0 筆`。不是 0 就停下回報，不要改腳本或 Sheet 硬過。
   - 數量應為：聯絡人 12（新增＋沿用）、出租單位 11、租約 11（生效 11）、期次 139、草稿帳單 66（2026-10 執行時是 5–10 月 × 11 間；跨到 11 月後執行會多 11 張）。
   - `⚠` 警告：負責人、縣市、行政區找不到，或聯絡人沿用既有資料並被改成 Sheet 的值，都要列給使用者看。
   - 「目標資料庫已有同名物件」：回到 3.2 處理舊資料。**不要**用 `ALLOW_DUPLICATE=1` 繞過。
9. 使用者確認後正式寫入：同一個指令加 `-e COMMIT=1`（`docker exec -i -e COMMIT=1 <容器> ...`）。腳本會再核對一次，差異 0 才 commit。
10. 寫入後再跑一次盤點腳本，確認新物件的單位、租約、期次、草稿帳單數量，以及舊物件的處理結果。

寫入後要撤銷的話，先問使用者，不要自己刪正式機資料。

## 4. 大安公館這份快照的資料決策

本機和老闆原始帳單（Sheet「羅斯福路公館整合」分頁）比對過，5–10 月 × 11 間共 66 筆應收合計全部一致（Sheet 最後一段有明細）。為了對齊老闆帳單，期次上做過這些手動調整，快照已經包含：

| 房間／月份 | 調整 | 原因 |
| --- | --- | --- |
| R2 2026-05 | 租金 0；入住電錶度數 8067 | 5 月空房未收租；Sheet 3 月讀數 0 是錯的，4 月是 8067 |
| R8 2026-05 | 租金 17500；上期度數改 3626（電費 0） | 老闆當月少收租金、沒算電費 |
| 2F上、2F下 2026-05～07 | 租金 14500 | 8 月起降租為 14000 |
| 2F上、2F下 2026-08～10 | 固定水費 0 | 8 月起免收水費；單位固定水費仍是 200，11 月起照收 200 |

其他：

- 房客姓名、電話、租約到期日是使用者依真實合約手動改過的，和「房間租約」分頁的 demo 資料不同。快照以 ERP 為準。
- 匯出時用 `READINGS_UNTIL=2026-09`：只帶抄表月份到 9 月的本期度數，11 月以後的期次本期度數留空（待抄表）。本機 R2 2026-11 有一張使用者自己測試用的已付款帳單（INV/2026/00005，本期度數 9500），以及其他房間 11 月的測試讀數，都不帶到正式機。
- 房東「羅斯福房東」的內部參考（project test）和備註是 demo 資料，原樣帶過去；要清掉的話先改 Sheet 再插入。

## 5. 重新產生快照

```bash
docker exec -i -e PROPERTY_CODE=PROP/2026/0134 -e READINGS_UNTIL=2026-09 ggandy_odoo19_web sh -c \
  'odoo shell -c /etc/odoo/odoo.conf -d ggandy_dev --db_host="$HOST" --db_port="$PORT" \
   --db_user="$POSTGRES_USER" --db_password="$POSTGRES_PASSWORD" --no-http --log-level=error' \
  < notebook/scripts/export_property_snapshot.py > /tmp/snapshot.csv
```

「對帳」段落是這次一次性附加的，重新匯出不會有。換別的物件只要改 `PROPERTY_CODE`，插入時用 `SHEET_URL` 指到新分頁的 CSV 匯出網址（`.../export?format=csv&gid=<分頁 gid>`）。

本機測試插入腳本：在腳本前面加一行 `CSV_TEXT = "<CSV 內容>"` 後餵進 odoo shell，並加 `ALLOW_DUPLICATE=1`（本機已有同名物件）。預設會 rollback，不會留下資料。

## 6. 之後要設計的地方（目前沒改程式）

- **改單位水電設定會覆蓋所有未過帳期次**：`ggandy.property.unit._sync_utility_settings_to_schedules()` 會把草稿／生效中租約裡、帳單還沒過帳的期次整批覆蓋，單月調整（例如 8–10 月免收水費）也會被蓋掉。可能的方向：改設定時指定「從哪個月起套用」，或同步時跳過單獨調整過的期次。
- **第一期電費**：期次收的是上個月的電費。新房客真的入住的第一期不該收；但這次從舊帳轉進來的房客，老闆 5 月照收 4 月電費（9 間合計 7,491）。要分「新入住」和「舊帳轉入」兩種情況。
