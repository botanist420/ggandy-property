# GGAndy 包租代管系統

GGAndy 是給包租代管公司使用的 Odoo 19 客製化 ERP。它把「房東、房客、物件、房間、租約、收租、維修、帳務」放在同一個系統裡，並把每月固定要做的事（開租金帳單、房東結算、逾期提醒、帳務總表）交給排程自動完成，讓老闆可以快速掌握公司營運狀況。

- Odoo 版本：19.0（Community，官方 `odoo:19.0` Docker image）
- 資料庫：PostgreSQL 17（`pgvector/pgvector:pg17-trixie`）
- 會計本地化：`l10n_tw`（台灣）
- 自訂模組：
  - `ggandy_property_management`：包租代管主模組
  - `ggandy_property_telegram`：Telegram 管理員 Bot
  - `ggandy_line_bot`：LINE 房客 Bot（房客查帳單、繳費方式、租約，自行改電話／Email）
  - `ggandy_property_project`：包租物件整備專案（串接 Odoo 專案、銷售、採購與分析會計）
- 後台主題：MuK Backend Theme（第三方，LGPL-3，見下方「後台主題」）

## 系統在管什麼

系統圍繞四種角色，全部都是 Odoo 的 `res.partner`，只靠勾選身分區分（同一個人可以同時是房東與房客）：

| 角色 | 說明 | 識別欄位 |
| --- | --- | --- |
| 房東 | 提供物件，和公司簽包租或代管合約 | `is_ggandy_owner` |
| 房客 | 和公司簽租約，每月繳租金、管理費與押金 | `is_ggandy_tenant` |
| 合作廠商 | 處理房屋維修、工程與採購（報修單、整備採購都只能選合作廠商） | `is_ggandy_vendor` |
| 公司內部人員 | 管理物件、收租、報修、結算（Odoo 使用者） | 權限群組 |

這些身分大多會自動勾選：建立物件／房東合約時勾房東，建立租約時勾房客，報修單選了廠商就勾合作廠商。
選人的欄位也會依身分篩選：房客租約的房客與共同居住人只能選房客，物件與房東合約的房東只能選房東，報修單的合作廠商、整備採購的供應商只能選合作廠商；在欄位上直接輸入新名字建立的聯絡人會自動勾好對應身分。

主要資料流程：

```text
房東 (res.partner)
  ↓ 房東合約 ggandy.owner.contract ──（每月房東匯款日）──→ 房東 Vendor Bill
物件 ggandy.property
  ↓
房間 ggandy.property.unit ──（格局照片 / 維修照片）
  ↓
房客租約 ggandy.lease
  ↓（租約生效時自動拆月）
收租明細 ggandy.rent.schedule ──（計費開始日到）──→ 房客租金 Invoice（草稿，收款時才過帳）
  ↓
GGAndy 帳務總表 ggandy.accounting.overview（每個房間 × 每個月一列，只看房客／房東租金收付）

報修單 ggandy.maintenance.request（獨立記錄，不進帳務總表）
```

## 日常商業流程

### 1. 建立物件與房間

每個管理中的房子先建立成「物件」，系統自動給物件編號（`PROP/2026/0001`）。物件記錄：

- 房東、內部管理人員
- 物件類型（整棟、公寓、透天、套房、商用…）
- 經營模式：包租或代管
- 地址：國家預設台灣；先選縣市（下拉選單台北市、新北市、桃園市排最前面），鄉鎮市區只會列出該縣市的區，選好後自動帶入郵遞區號
- 開始管理日、管理截止日
- **房東匯款日**：每月匯款給房東的日期，新增房東合約時會自動帶入合約；之後在物件上修改，生效中房東合約的匯款日也會跟著改（草稿、已到期的合約不動）

物件列表右上角可以切換成**卡片**檢視：每張卡片顯示經營模式、房東、地址、房間數、已出租數與出租率進度條，列表也多了「出租率」欄。房間列表多了「目前房客」與「租期結束」（今天落在租期內的生效租約）。房間也可以切換成**卡片**（手機預設就是卡片），依物件分組，每張顯示出租狀態、房型／坪數／樓層、目前房客、月租（空房顯示參考月租）。物件地址選好鄉鎮市區會自動帶入郵遞區號（欄位隱藏，鄉鎮市區名稱後面就看得到）。

物件表單上方的按鈕依序是房東合約、房間、房客租約、報修單。物件還沒有草稿或生效中的房東合約時（包含舊合約都已到期／終止），表單上方會出現藍色的「**新增房東合約**」按鈕，按下去會帶好房東、經營模式、管理期間與匯款日；建好草稿合約後按鈕就會消失。

物件頁右下角的「**本月收租概覽**」即時加總本月帳單（跟「當期帳單」分頁同一批收租明細，但金額只算生效中、已到期、提前終止的租約，草稿租約不算，和帳務總表一致），順序照老闆付房東的 Google Sheet：房客租金、管理費、網路第四台、電費、水費、合計，最後一行是「**應付房東**」（保底租金或代管已收租金扣代管費，加上管理費、網路第四台、電費、水費）。網路第四台是物件上每月固定的金額，直接在概覽裡編輯；它不會開進房客帳單，但會轉付給房東。電費是本月帳單收的上個月用電。

物件頁的「當期帳單」分頁會列出這個物件所有房間本月的收租明細（租金、管理費、水電、應收合計、收款狀態），依房間順序排列，只供檢視；要建帳單或修改金額請到收租明細或租約。

物件頁的「**Lucas統計**」分頁（暫名，正式上線前改回「數據分析」）在開啟物件時即時整理近 12 個月的數據（不存資料庫）：KPI（出租率、時間加權出租率、平均／中位數月租、每坪月租、收款率、準時繳款率、預計賺）、租金描述統計（n、平均、中位數、標準差、CV、四分位數、IQR 離群）、各房間明細（z 分數、比參考月租、平均用電、準時率）、月度趨勢（取自帳務總表）、收款延遲分布（付款日以帳單沖銷日計算）、水電異常（高於平均＋2σ、出租中卻 0 度）、租約周轉（平均租期、換房客空窗、空房已空幾天），包租物件另有保底價差、毛利率與損益兩平出租率。每坪數字需要房間填坪數；樣本數小於 5 時僅供參考。表頭與 KPI 上有虛線的統計名詞，游標停上去會看到一句白話說明，頁尾也有可展開的「名詞解釋」。

「房間」分頁每一列有「🏠房間」（開房間頁面）與「📄租約帳單」（直接開這間房目前的租約，可在收租明細分頁修改管理費、帳單等：生效中優先，其次草稿，再來是最近開始的那份；沒有租約就開租約列表）兩個按鈕。這個分頁預設顯示每度電價（電費依度數計費才顯示）與水費（水費每月固定金額才顯示），房間類型、樓層、坪數預設隱藏，可從右上角欄位選單勾選。物件頁的房間、當期帳單、水電表維護分頁都依房間的排序：預設照新增的順序（通常就是房東 Google Sheet 的房間順序），可在房間分頁拖曳每列左邊的把手調整，按分頁底下的「新增房間」加入的房間會排在最後。物件頁與房間頁的「房客租約」smart button 列出該物件／房間的所有租約。

物件底下可以有多個房間（套房、雅房、整層、店面、辦公室、車位）。新增房間時，電費預設「依度數計費」、水費預設「每月固定金額」。房間記錄房號、樓層、坪數、房間／衛浴數、參考月租、押金月數與出租狀態（空房／已保留／已出租／維修中／停用）。

每個房間也記錄**水電費怎麼收**，電費、水費各自設定：

- 計費方式：依度數計費／每月固定金額／含在租金內／房客自繳（台電、水公司）。
- 依度數計費時填「每度電價／每度水價」，每間房可以不同（例如 5、5.5、4 元）。算法是 **（本月度數 − 上月度數）× 每度單價**。
- 每月固定金額時填固定電費／水費；另可記錄電錶、水錶編號或位置，抄表時對照用。
- 單價改動會留在 chatter，方便日後對帳。房間的設定是**新租約的預設值**：建立租約時會複製到租約上，之後收費和合約 PDF 都照租約。所以改房間的設定只會影響新租約和草稿租約；生效中的租約要調單價，請到租約的「水電計費」直接改，會更新那份租約還沒過帳的收租明細。

**抄表與水電費**（依度數計費時）：

- 租約上填「入住電錶／水錶度數」（點交時抄的度數），選房間時會預設帶入該房間最近一次抄表的度數。
- 租約的「收租明細」分頁會多出 電錶上期／本期、電費、水錶上期／本期、水費 欄位（只顯示該房間有用到的）。
- 每次抄表後，在該期填「本期度數」即可：系統算出 用量 = 本期 − 上期、費用 = 用量 × 每度單價（四捨五入到元），並自動把這個度數帶到下一期的「上期度數」。中間某期沒抄，下次抄表會累計兩期的用量。
- 本期度數不可小於上期度數；換錶時請手動把該期的上期度數改成新錶的起始度數。
- 帳單還是草稿時，改度數或單價會同步更新帳單上的水電行；帳單過帳後就鎖住，抄錯請在下期調整或另開補收／折讓帳單。
- 收租明細可用「還沒抄表」篩選：依度數計費、已開始計費但還沒填本期度數的收租明細。
- **電表月份**：M 月電表（M 月底的讀數）寫進 **M+1 月收租明細**的本期度數，也就是 10 月帳單收 9 月電費（9 月電表 − 8 月電表）。水電表維護分頁、租約的收租明細、收租明細頁都顯示「電表月份」，避免把 10 月收租明細的度數誤認成 10 月的電表；收租明細本身的月份叫「帳單月份」。
- **水電表維護分頁**：物件頁（只列本月帳單，所以電表月份是上個月；依房間順序）與房間頁（該房間每份租約起訖之間的所有月份，最新月份在上面）都有「水電表維護」分頁，可直接填抄表度數並看到電費，水費每月固定金額的房間也能直接改那一期的「水費」（只改那一期，之後每月的金額請改房間的水費設定；水費依度數計費時可從欄位選單打開「水錶度數」）。它編輯的就是收租明細上的「電錶本期度數」與「固定水費」，所以上面這些連動（帶到下一期、更新草稿帳單、過帳後鎖住）都一樣；只列出電費依度數計費或水費要另外收（依度數／每月固定）、租約未取消的收租明細。

- **快速抄表**：物件頁上方的「快速抄表」按鈕會開一個小視窗，選電表月份（預設本月，只能選本月與過去 11 個月），視窗會列出系統裡的房間順序（就是物件頁房間分頁的順序），確認跟 Google Sheet 一致後，把 Sheet 上該月的「度數那一列」貼上即可，度數依序對應到房間（tab 分隔、千分位逗號自動去掉，連 A 欄的「9月」一起複製也可以）。順序不一致請先到房間分頁拖曳調整。按「預覽」後會列出每間房的帳單月份、上期 → 本期度數、用電度數與狀態，確認無誤按「確認寫入」，要改就按「返回修改」。度數空白或 0 會略過；格數跟房間數對不起來會直接提示；該月沒有租約收租明細、度數小於上期、帳單已過帳的房間不會寫入，會在結果通知列出。寫入走跟水電表維護分頁一樣的連動。**一次補好幾個月**：連 A 欄的月份（例如 `9月`、`2026/9`、`2026-09`）一起複製多列貼上，上方的電表月份就不用選，系統會依每列的月份由舊到新檢查與寫入，預覽也會依月份分段；同一間房上個月也在這次貼上的範圍內時，「上期度數」用貼上的值。月份重複、還沒到的月份、認不出來的月份會直接提示是第幾列。

房間頁面上方有「新增房客租約」按鈕，會直接開新租約並帶入物件、房間、月租與押金；這間房還沒有草稿或生效中的租約時按鈕會以主色顯示，已有租約時改為一般按鈕（續約或預訂下一位房客時仍可使用）。

房間頁面另外有兩個照片分頁（分頁順序：租約紀錄、水電表維護、格局照片、維修紀錄、維修照片、備註）：

- **格局照片**：在該房間的 chatter 用迴紋針上傳圖片，就會自動出現在這裡。
- **維修照片**：自動彙整這個房間所有報修單（含已封存）chatter 上的圖片，依報修時間由近到遠排列。

> 物件也可以從 Google Sheet 批次匯入（見「整合工具」）。

### 2. 建立房東合約

房東合約代表「公司和房東之間怎麼合作」，編號 `OWNER/2026/00001`。

| 合約類型 | 每月應付房東 |
| --- | --- |
| 包租 | 每月保底租金（不論房客是否已繳）＋ 代收轉付項目 |
| 代管 | 當月實收租金 − 代管費（百分比或固定金額，新合約預設 8%；當月沒收到租金就不扣固定費）＋ 代收轉付項目 |

**代收轉付項目**：物件「本月收租概覽」上的管理費、網路第四台、電費、水費，依帳單月份原封不動加進房東帳單，每項一行，0 元的不列。例如大安公館 10 月：保底 147,140 ＋ 電費 12,665 ＋ 水費 1,700 ＝ 161,505。固定扣除與當月調整還沒做進系統。

- 同一物件在同一期間只能有一份「生效中」的房東合約。
- 新建合約選了物件，會預設帶入房東、經營模式、匯款日，以及物件的「開始管理日／管理截止日」當合約起訖（已經填了就不覆蓋）。從物件頁按「新增房東合約」時，物件、房東、合約類型直接照物件鎖定（物件還沒填的才可以選），游標會停在「每月保底租金」；合約生效時，再把合約的房東、經營模式、起訖日同步回物件。
- 每天排程會檢查：到了當月「房東匯款日」（小月遇到 29–31 號自動用月底），就替合約建立當月房東 Vendor Bill，同一個月不會重複建立。結算一律依**帳單月份**。
- **帳單調整**：房東合約的「帳單調整」分頁記某個月房東帳單要多付或少付的錢：少付填負數（例如不付 9F 租金＋管理費填 −32,000），多付填正數（例如退 R2 押金填 +29,000），帳單月份直接填年-月（例如 2026-09），每筆會在那個月的房東帳單多一行，按「重新計算房東帳單」也不會被蓋掉；物件的「應付房東」也會算進去。那個月還沒開帳單的話，開帳單時自動帶入；帳單已經開好了才新增的調整，按列表右上方的「**插入帳單**」加進草稿帳單（已過帳的帳單不會動，會提醒先重設為草稿）。插入後這列變灰、鎖定不能改或刪，旁邊顯示加進哪張帳單；要改請先到帳單刪掉那一行，或取消帳單，調整就會解鎖。
- **一個月只有一張房東帳單**：排程在房東匯款日建立；還沒到匯款日也可以在合約上方按「**開立本月房東帳單**」先開（需要會計「開立發票」以上權限）。這個月已經有帳單時，不論是排程開的還是手動開的，按了都會直接打開那張，不會再開新的。
- **補開歷史房東帳單**：合約從過去的月份起算（例如 10 月才建檔、合約 5/1 起），按「合約生效」後會自動跳出精靈，列出房東匯款日已過、還沒開房東帳單的月份（例如 5～9 月），每月分欄顯示保底（或代管實收）、管理費、網路第四台、電費、水費、帳單調整與合計（0 元也會列出）。勾選後按「建立草稿帳單」，帳單日期用各月匯款日，全部是草稿，之後還能改或重新計算。已經生效的合約，合約上方會出現「補開歷史房東帳單」按鈕（有缺月份才顯示）。同一個月一樣只會有一張。如果是按錯「合約生效」，精靈上的「退回草稿」可以把合約退回草稿（已經開了房東帳單就不行，要先取消帳單）。
- **重新計算房東帳單**（包租、代管都可以）：房東帳單建立後，抄表度數、管理費、網路第四台有改，或代管有房客晚繳，到那張帳單按「重新計算房東帳單」：帳單還是草稿，明細會整批換成新算出來的（手動改過的明細會被覆蓋）；已經過帳就**不會自動調整**，只會告訴你重算後差多少，由同事自己決定怎麼處理。

### 3. 建立房客租約

房客租約代表「公司和房客之間怎麼收租」，編號 `LEASE/2026/00001`。記錄物件、房間、房客與共同居住人、租期、每月租金、管理費、押金與每月繳租日。

- 選房間時會自動帶入參考月租與押金（參考月租 × 押金月數）。
- **租約列表**依「物件 → 物件裡設定的房間順序」排列，顯示房客電話、租期、月租、管理費；生效中的租約 30 天內到期、又還沒找到下一位房客時，「租期結束」會變成紅色粗體。租約編號、押金、繳租日可從欄位選單勾選顯示。
- 收租明細已建立後，「計費開始／計費結束／繳款期限」就不能再改（租約的收租明細分頁與收租明細頁面都一樣）；手動新增的收租明細在存檔前仍可填日期。
- 同一房間在同一期間只能有一份生效租約。
- 租約生效後：依月份自動拆出收租明細（月中入住／退租的那一期，租金與管理費依當月實際天數按日計算，四捨五入到元），並立即替這份租約已到期的收租明細開立 Invoice。
- **房間出租狀態看日期**：今天落在某份生效租約的租期內才算「已出租」。預約下個月入住的租約生效後，房間仍是空房，到了起租日由每天排程自動改成已出租；租約到期、終止或取消後，沒有其他生效租約就變回空房（「已保留／維修中／停用」不會被自動改）。
- 已有過帳帳單的租約不能退回草稿或取消。
- **提前終止**：按「提前終止」填終止日（預設今天），系統會刪除終止日之後還沒開帳單的收租明細，帳務總表也不再計算；終止日所在那個月的租金不會自動按日重算，請到收租明細手動調整。終止日會顯示在租約上。
- **自動到期**：每天排程會把租期結束日已過、還是「生效中」的租約改成「已到期」（chatter 留紀錄），房間沒有其他生效租約就變回空房。已到期租約沒繳的租金照樣會出現在逾期提醒，退租當月也還能抄表。
- **續約**：生效中或已到期的租約，按上方「續約」填新租期結束日（預設多一年）與續約後月租／管理費，系統會延長**同一份租約**、從原結束日隔天起補建收租明細並開立已到期的帳單；新月租只套用在延長的期間，已建立的收租明細金額不變。已到期的租約續約後會改回生效中。同房間已經有下一份租約排在延長期間內時不能續約。
- **產生租約 PDF**：草稿或生效中的租約，按上方「產生租約 PDF」（或「列印」選單）就會下載公司正式的「房屋租賃契約」（四頁，條文與紙本相同），底線處依資料帶入：
  - 出租人（甲方）：包租物件是公司、代管物件是房東（公司列為代管業者丙方）。
  - 承租人：印姓名，聯絡人上有填的身分證號（稅號）、電話、E-mail 也會印；出生日、戶籍、公司、緊急聯絡人留空讓房客自己寫。
  - 租期（民國年、共計幾年／幾個月）、地址範圍（物件地址＋房間樓層＋房號）、租金、押金、繳租日；水電依房間的計費方式印出（例如每度 5.5 元＋入住電錶度數、水費每月固定 200 元）。
  - 繳款帳戶：收款方聯絡人上的第一個銀行帳戶，分行留空手寫。
  - 設備點交表印合約範本的設備與賠償單價，數量在點交時手寫；各處簽名與日期也都留空。「合約備註」印在第七條其他特約事項。
- **房客待續約**（合約管理 → 房客待續約）：列出快到期、要談續約的租約，依到期日排序，顯示房客電話與剩餘天數（7 天內紅色、30 天內黃色），每列都有「續約」按鈕。預設篩選「30 天內到期」，搜尋列可改成「90 天內到期」或「最近 30 天剛到期」；同房間已經有下一份租約（續租或新房客，草稿也算）的不列出。
- **合約文件分頁**：把簽好名的合約、公證書、點交照片用租約 chatter 的迴紋針上傳，就會自動彙整在最後一個分頁（圖片顯示縮圖，PDF 等檔案顯示圖示，點了在新分頁開啟）。

### 4. 收租與帳單

每月租金先成為「收租明細」，再由收租明細建立客戶 Invoice（租金、管理費、電費、水費各一行，金額為 0 的不列）：

- 每天排程：計費開始日已到、還沒開單的收租明細自動開 Invoice（生效中與已到期的租約都算）。
- 每天排程：已逾期未收齊的收租明細，替物件管理人員建立「逾期租金待處理」活動；收款後活動會自動結案。
- 收租狀態：尚未開單、草稿帳單、待收款、部分收款、已收款、已逾期、已取消。
- 「房客收租明細」列表依「帳單月份（新到舊）→ 物件 → 房間順序」排列；搜尋列可快速篩「本月／上月／下個月」與「逾期未繳／還沒收到錢／已收款／還沒開帳單／還沒抄表」，也能依帳單月份分組。
- 「房客收租明細」選單預設篩選**本月**（依帳單月份）並依物件分組，也可以改看「上月」；「房客租約」選單預設依物件分組。
- **帳單平常維持草稿，房客付了錢才正式過帳**：草稿帳單的抄表、金額都還能改。房客匯款後，在「逾期未收」或收租明細列表勾選要收款的收租明細（可跨房客、跨物件），按上方「登記收款」：還沒開單的先開單、草稿帳單自動「確認」（過帳），接著打開 Odoo 原生的「付款」視窗，選收款日與銀行／現金後確認即可。同一位房客的多張帳單可以勾「分組付款」合成一筆。需要會計「開立發票」以上權限才看得到這個按鈕。
- **金額一律未稅**：GGAndy 的租金、管理費、水電、房東結算、包租服務費等產品都不帶營業稅。

收租明細是營運管理用的角度，Invoice 是會計與收款用的角度。

### 5. 報修與維修費用

報修單（`REPAIR/2026/00001`）記錄物件與房間、報修房客、維修類型、優先度、內部負責人、合作廠商、預估／實際費用，以及費用由公司、房東、房客或待確認負擔。

- 選房間時自動帶出目前生效租約與房客。
- 流程：待處理 → 已指派 → 處理中 → 等待料件 → 已完成（完成前必須填寫處理結果）。
- 維修照片直接上傳到報修單 chatter，會自動彙整到房間的「維修照片」分頁。

## GGAndy 帳務總表

選單「包租代管 → 帳務 → 營運總表」是給老闆看整體營運狀況的地方。右上角可以切換**樞紐分析**（物件 × 月份，看應收、實收、應付房東、預計賺）與**圖表**（依月份長條）；「房客收租明細」也有樞紐分析（物件 × 帳單月份的應收合計）。

總表只呈現**房客與房東的租金收付**，刻意不算整備與報修成本；金額一律未稅，只算生效中、已到期、提前終止的租約（草稿、取消的不算）。它以 **每個房間、每個月份** 為一列：每個啟用中的房間，從建立月份（或更早的第一份租約開始月）一路列到本月，資料列自動產生，不需要排程或手動更新；所有金額都是開啟時即時從收租明細與帳單算出：

| 欄位 | 計算方式 |
| --- | --- |
| 租金應收 | 當月收租明細的應收合計（租金 + 管理費 + 水電費） |
| 租金實收 | 已收款的租金帳單金額（未稅） |
| 應付房東／已付房東 | 當月房東 Vendor Bill（未稅），依房間參考月租比例分攤到各房間（無參考月租則平均分攤） |
| 預計賺 | 租金應收 − 應付房東：這個月的帳照收照付的話可以賺多少 |
| 已經賺到 | 租金實收 − 已付房東：到今天為止，這個月的帳實際落袋多少 |

- 預設篩選本月、依物件分組，每個物件有小計、最下面有總計（也可以依月份、房間、房東分組）。
- 顏色只用在需要注意的地方：還有租金沒收齊時「租金實收」顯示橘色、還有款項沒付房東時「已付房東」顯示橘色、「已經賺到」為負時顯示紅色，其他都是黑字。
- 可以用「本月／上月／還有租金沒收／還沒付房東／目前賠錢」快速篩選。
- 總表只能看不能改；要調整數字，請改收租明細或帳單。

> 「預計賺」和「已經賺到」差很多，就表示還有錢沒收、或還沒付房東。兩者都依帳單月份歸屬，不等同會計損益。

同一個選單底下另外有：

- **逾期未收**：生效中租約、過了繳款期限還沒收齊的收租明細，預設依物件分組，租金、管理費、水電、應收合計都有小計與總計。
- **待付房東**：房東合約建立、還沒付清的 Vendor Bill（預設篩選「待付款」，拿掉可看全部）。需要會計「開立發票」以上權限才看得到這個選單。

## Telegram 行動指揮中心

`ggandy_property_telegram` 是給「包租代管 / 管理員」群組使用者的行動查詢工具。

| 指令 | 內容 |
| --- | --- |
| `/status` | 今日營運摘要：管理物件數、出租中／空房、本月應收／已收／未收、逾期租金、待處理維修、一個月內到期租約 |
| `/overdue` | 逾期租金清單（前 10 筆與未收合計） |
| `/renew` | 續約提醒：一個月內到期的租約，附房客電話／email、共同居住人、租期、月租、押金、剩幾天；另列「近 30 天已到期、還沒有下一份租約」的租約。同房間已有下一份租約的不列出（與「房客待續約」選單相同）。可帶天數，例如 `/renew 60`（1–365）。舊指令 `/leases` 也會回傳一樣的內容 |
| `/maintenance` | 待處理維修 |
| `/start`、`/help` | 指令說明 |

設定方式：

1. 包租代管 → 整合工具 → 設定（需系統管理員），在「Telegram Bot」區塊：填入 BotFather 給的 Bot Token，按「測試 Telegram 連線」，並勾選「本機輪詢模式」。
2. 使用者私訊 Bot 傳 `/start`，Bot 會回覆該使用者的 Telegram User ID。
3. 到 Odoo 使用者頁面填入 Telegram User ID，並勾選「允許使用 GGAndy Telegram Bot」（使用者必須是包租代管管理員）。

Bot 透過 Odoo 排程每分鐘向 Telegram `getUpdates` 拉訊息，不需要公開 webhook，localhost 也能用。只接受私訊，所有收發紀錄都會留存。另外每天會把逾期租金摘要主動推播給已綁定的管理員。收發紀錄在「包租代管 → Telegram → 訊息紀錄」。

## LINE 房客 Bot

`ggandy_line_bot` 讓房客用公司的 LINE 官方帳號自己查帳單。Bot **只回覆房客按的選單**（Reply API 不計訊息則數），不主動推播，LINE 輕用量免費方案就夠。申請官方帳號、圖文選單與歡迎訊息的設定步驟見 [notebook/docs/line-bot-plan.md](notebook/docs/line-bot-plan.md)。

| 房客傳送（圖文選單） | Bot 回覆 |
| --- | --- |
| `帳單` | 本月帳單＋之前還沒繳清的帳單：租金、管理費、水電（含度數）、合計、繳租日、狀態、尚未繳清合計 |
| `繳費` | 收款銀行、帳號、戶名、繳租日（收款方判斷與租約 PDF 相同） |
| `租約` | 物件／房間、租期與剩餘天數、月租、押金、繳租日 |
| `修改資料` | 目前的電話、Email；房客傳 `電話 0912345678`、`email abc@example.com` 直接更新，並記在聯絡人 chatter |
| `帳單歷史`（打字） | 最近 3 期帳單 |
| `報修 馬桶壞掉`（打字） | 建立報修單 `[房客通報] 馬桶壞掉`（負責人＝物件管理人員，並排待辦活動）；30 分鐘內傳的照片附到報修單 chatter，最多 3 張 |
| `聯絡管理員`、`說明` | 房間管家（物件的管理人員）姓名與電話／功能說明 |

目前沒有真人客服：其他留言、貼圖、照片 Bot 會回提示，請房客用選單或聯絡房間管家。

設定方式：

1. 包租代管 → 整合工具 → 設定：擴充模組勾「LINE 房客 Bot」並儲存；在「LINE 房客 Bot」區塊貼上 Channel secret、Channel access token，按「測試 LINE 連線」。
2. 把設定頁顯示的 Webhook URL（`https://<網域>/ggandy/line/webhook`）貼到 LINE Developers Console，按 Verify 並開啟 Use webhook。必須是公開的 https 網址，且 Odoo 只有一個資料庫（或設了 `dbfilter`）。
3. 房客綁定：房客聯絡人 →「包租代管」分頁 →「產生 LINE 綁定碼」，複製說明傳給房客；房客加好友後傳「綁定碼 123456」或直接傳「123456」。綁定碼 1 天有效、用過即失效，只開放租約上的主要房客。

收發紀錄在「包租代管 → LINE → 訊息紀錄」（「看不懂的訊息」篩選房客傳了哪些 Bot 看不懂的內容），已綁定的房客在「LINE → 已綁定房客」。

## 包租物件整備專案

`ggandy_property_project` 用 Odoo 原生「專案」追蹤包租物件從簽約到上架前的整備期，並讓這段期間的銷售與採購能被專案與會計分析。

1. 經營模式為「包租」且已設定主要房東的物件，form 上方會出現「開始整備」按鈕（僅包租代管管理員）。
2. 按下後自動建立 `整備-{物件名稱}` 專案：勾選可計費、客戶為主要房東，並建立同名分析帳戶（分析計畫「專案」）。每個物件只能建立一次，之後按鈕改為「整備專案」智慧按鈕（顯示任務完成進度，例如 4/12 (33%)，取消的任務算完成）。
   同時會：
   - 建立一張給房東的銷售單並自動確認（客戶 = 房東、專案 = 整備專案），預帶一行 0 元「包租服務費」，金額之後到銷售單調整。專案的「銷售訂單」是從銷售明細找單的，空單在專案裡看不到，所以一定要有這一行。專案已有給房東的銷售單就沿用；沿用的單沒有明細時也會補上這一行。
   - 廠商帳單要不要轉到這張單向房東請款，由**產品**的「重新開立發票成本」決定：可向房東請款的設「按成本」或「按銷售價」，過帳時自動加到銷售單；公司自行吸收的家具、裝潢等設「否」，成本只進整備專案的分析帳戶（專案獲利能力看得到），不會加到銷售單。
   - 在總倉底下建立庫存位置 `WH/庫存/{物件名稱}/{房間}`（已有同名位置就沿用），方便收貨直接入房、內部調撥與看房間物品清單（庫存 → 報告 → 位置）。之後新增房間，按「同步庫存位置」即可補齊。
3. 專案階段與任務複製自「整備範本」專案（專案 App 的範本，可直接在畫面上修改任務內容）：
   評估簽約 → 規劃預算 → 採購發包 → 施工驗收 → 上架招租 → 整備完成／已取消。
4. 建立整備專案後，包租物件 form 上方會多一個「整備採購」按鈕（需採購權限），會直接開新的採購單並帶好整備專案。專案是整備專案的採購單，供應商只能選「合作廠商」。
5. 向房東收費開**報價單**、工班與家具家電開**採購單**時，在「專案」欄選這個整備專案（用「整備採購」按鈕開的採購單已自動帶好）：明細會自動帶入分析帳戶，帳單也跟著帶，專案的「獲利能力」面板與會計分析報表就能看到收入與成本。
6. 可向房東請款的「商品」類產品，廠商帳單過帳轉到房東銷售單時，Odoo 會自動產生一張交貨單（WH/庫存 → Customers）。若東西要留在房間，請**取消這張交貨單**，改用內部調撥放進房間；請款不受影響。

## 整合工具

選單「包租代管 → 整合工具」：

- **設定**（僅系統管理員）：開到「設定 → 包租代管」頁面，所有 GGAndy 相關設定都集中在這裡：
  - **擴充模組**：勾選「Telegram 管理員 Bot」、「LINE 房客 Bot」、「物件整備專案」後儲存就會自動安裝；取消勾選會解除安裝並刪除該模組資料（Odoo 會先跳確認）。
  - **Telegram Bot**：Bot Token、測試連線、本機輪詢（裝了 Telegram 模組才會出現）。使用者綁定仍在使用者頁面的「GGAndy Telegram」分頁。
  - **LINE 房客 Bot**：Channel secret／access token、測試連線、Webhook URL、清除所有綁定（裝了 LINE 模組才會出現）。房客綁定在聯絡人頁的「包租代管」分頁。
  - **整備專案**：「編輯整備範本」連結（裝了整備專案模組才會出現）。
  - **Google Sheet 匯入**：物件／聯絡人匯入精靈預先帶入的連結，留空使用內建連結。
- **從 Google Sheet 匯入物件**：貼上 Google Sheet 連結（需可公開讀取），欄位為 `編號`、`案件名稱`（必填）、`經營模式`（包租／代管）、`房東`、`地址`、`管理人員`、`匯款日期`（例如 `30號`）、`出租單位`（房號用半形逗號隔開，例如 `201,202,店面`）。用 `編號 + 案件名稱` 產生穩定的 external id，重複匯入會更新同一筆物件，不會重複建立；留空的欄位不會覆蓋既有資料。房東依名稱比對聯絡人，找不到時預設自動建立房東聯絡人；管理人員依名稱或登入帳號比對內部使用者，找不到就留空，並在匯入結果以警告列出「編號／案件名稱／管理人員」。房間只新增物件底下還沒有的房號，不會刪除。
- **從 Google Sheet 匯入聯絡人**：貼上 Google Sheet 連結，預設讀取 `gid=0` 分頁，表頭為 `partner_key`、`name`（必填）、`phone`（手機或市話都填這格）、`email`、`street`、`city`、`zip`、`is_owner`、`is_tenant`、`is_vendor`（填 `TRUE` / `FALSE`）。依 `partner_key → email → 電話 → 名稱` 找既有聯絡人，找到就更新、找不到才新增；同一條件對到多位時整列略過並提醒。留空欄位不覆蓋；身分旗標只加不減。舊表頭的 `mobile` 已停用，留著也不會匯入。
- **從 Google Sheet 匯入租約與抄表**：一份 Sheet 三個分頁（每列一筆、第一列為中文標題），可只填需要的分頁：
  - **房間租約**（一間房一列）：`物件編號`、`房號`、`房客`、`起租日`、`到期日`、`月租`、`電費方式`、`水費方式`（必填），`房客電話`、`押金`、`繳租日`、`每度電價`／`固定電費`、`入住電錶度數`、`每度水價`／`固定水費`、`入住水錶度數`（選填）。更新房間水電設定，建立或更新**草稿租約**並產生收租明細；以「房號＋起租日」辨識同一份租約，房客先比電話再比名稱，找不到就新增。
  - **抄表度數**（每房每月一列）：`物件編號`、`房號`、`抄表月份`（`2026-09`，就是電表月份）、`電錶度數`、`水錶度數`。填**月底讀數**，M 月讀數寫入 **M+1 月收租明細**的本期度數（下個月帳單收上個月水電）。
  - **帳單調整**（只放例外）：`物件編號`、`房號`、`帳單月份`、`租金`、`水費`、`電費（核對用）`、`備註`。留空沿用租約，填 0 代表不收；電費只核對不寫入，不符時列警告。
  - 先按「預覽」完整跑一次但不寫入，再按「匯入」。重複匯入只更新、不重複建立；已過帳的收租明細不改。電費高於月租（通常是入住度數填錯）會列警告。租約匯入後是草稿，到租約按「生效」才會開帳單。三個分頁的預設連結可在「設定」裡填。
- **包租獲利試算**（僅管理者）：跟房東談包租前先試算划不划。輸入房間數、初始投入、免租裝潢期、包租期間、每間付房東、每間預估月租、出租率，即時算出每月與整段期間的賺賠、投資報酬率、年化報酬率（ROI）、幾個月回本，以及出租率、月租、付房東的不賠底線。純試算，不會寫入任何資料；尚未扣水電、維修、人事與稅。
- **版本資訊**：選單最下面，開頭是 Lucas 的開發感想，下面依版本列出新功能、改善與修正（最新的在最上面），**每週更新一次**。所有使用者都看得到。

## 後台主題（MuK）

後台使用 MuK IT 的 **MuK Backend Theme 19.0.1.4.9**（[apps.odoo.com](https://apps.odoo.com/apps/themes/19.0/muk_web_theme)，LGPL-3，2026-10 導入），讓 Community 版有較好的手機版面與後台外觀。由 7 個模組組成，`muk_web_theme` 依賴其餘 6 個，安裝時會一併裝上；`muk_web_refresh` 另外會帶入 Odoo 官方的 `base_automation`。

| 模組 | 功能 |
| --- | --- |
| `muk_web_theme` | 主題本體：手機友善版面、App 選單背景圖、公司 favicon |
| `muk_web_appsbar` | 左側 App 側欄（每位使用者在「我的偏好」選大／小／隱藏） |
| `muk_web_chatter` | 留言區放右側或底部（每位使用者自選） |
| `muk_web_dialog` | 彈出視窗可切換全螢幕 |
| `muk_web_group` | 列表／看板分組「全部展開／全部收合」（搜尋列下拉選單） |
| `muk_web_refresh` | 控制列重新整理按鈕（雙擊每 30 秒自動刷新）；自動化規則可用「Reload Views」動作 |
| `muk_web_colors` | 「設定 → 一般設定」用顏色選擇器改品牌色／主色／狀態色 |

- **第三方程式碼不要直接修改**：要調整外觀寫在 `ggandy_property_management/static/src/scss/ggandy_backend.scss`；升級主題時整包換成 apps.odoo.com 的新版資料夾，再 `-u muk_web_theme`。
- **未來若更換主題**：`muk_web_group`（全部展開／收合，日常作業很方便）與 `base_automation`（自動化規則，可設定續約提醒、報修分派等輕量規則）建議**保留**，兩者都不依賴 `muk_web_theme`，可單獨留著；只解除安裝 `muk_web_theme` 與其他不需要的 muk 模組即可。
- Odoo Community 的 `ir.http.color_scheme()` 固定回傳 `light`，所以**沒有深色模式**；`muk_web_colors` 的深色配色設定只在 Enterprise 有作用。

## 開發與測試環境

### 服務與連接埠

| 項目 | 值 |
| --- | --- |
| Odoo Web | <http://localhost:1025> |
| Odoo WebSocket / gevent | `localhost:1026` |

| Odoo container | `ggandy_odoo19_web` |
| PostgreSQL container | `ggandy_postgres17_db` |
| 開發資料庫 | `ggandy_dev` |

### 第一次啟動

```bash
cp docker/ggandy/config/ggandy.env.example docker/ggandy/config/ggandy.env
# 修改 ggandy.env 的 POSTGRES_PASSWORD，以及 odoo.conf 的 admin_passwd
docker compose -f docker/ggandy/docker-compose.yml up -d
```

開啟 <http://localhost:1025> 建立資料庫後，到 Apps 安裝「GGAndy 包租代管」、「GGAndy Telegram 管理員 Bot」與「GGAndy 物件整備專案」（會一併安裝專案、銷售、採購模組）。開立帳單前請確認公司國家為台灣且已安裝會計本地化（需要銷售／採購日記帳）。

### 更新模組

修改 Python 或 XML 後：

```bash
docker exec ggandy_odoo19_web sh -c 'odoo -c /etc/odoo/odoo.conf -d ggandy_dev \
  --db_host="$HOST" --db_port="$PORT" --db_user="$POSTGRES_USER" --db_password="$POSTGRES_PASSWORD" \
  -u ggandy_property_management --stop-after-init --no-http'
docker restart ggandy_odoo19_web
```

改到其他模組時，把 `-u` 換成對應模組名稱（例如 `-u ggandy_property_project`，可用逗號一次升級多個）。

### 正式機升級

正式機與開發環境使用同一份 Docker Compose（`./addons` 掛載到 `/mnt/extra-addons`），容器與資料庫名稱也相同（資料庫都是 `ggandy_dev`），所以 `git pull` 拿到新程式碼後升級模組即可。

**一定要先 `cd` 到專案根目錄**再執行：`docker exec` 在哪個目錄都能跑，但 `git pull` 只能在專案裡跑，不在專案目錄時會出現 `fatal: not a git repository`，程式碼沒更新，後面的升級等於白跑。不確定專案在哪，可以查容器掛載的 addons 路徑（專案根目錄是 `docker/ggandy/addons` 的上三層）：

```bash
docker inspect ggandy_odoo19_web --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}' | grep extra-addons
```

```bash
cd /path/to/ggandy    # 專案根目錄（有 README.md 與 docker/ 的那層）

CONTAINER=ggandy_odoo19_web
DB_CONTAINER=ggandy_postgres17_db
DB=ggandy_dev

# 1. 備份資料庫與 filestore（升級前一定要做）
docker exec "$DB_CONTAINER" sh -c "pg_dump -U \"\$POSTGRES_USER\" -Fc $DB" > "backup_${DB}_$(date +%Y%m%d_%H%M).dump"
docker exec "$CONTAINER" tar czf - -C /var/lib/odoo/filestore "$DB" > "filestore_${DB}_$(date +%Y%m%d_%H%M).tgz"
ls -la backup_${DB}_* filestore_${DB}_*    # 確認檔案存在且大小不是 0

# 2. 取得新程式碼（失敗就停下，不要往下跑）
git pull --ff-only && git log --oneline -1

# 3. 升級自訂模組 + 安裝（或升級）主題；未安裝的模組會被略過
docker exec "$CONTAINER" sh -c "odoo -c /etc/odoo/odoo.conf -d $DB \
  --db_host=\"\$HOST\" --db_port=\"\$PORT\" --db_user=\"\$POSTGRES_USER\" --db_password=\"\$POSTGRES_PASSWORD\" \
  -u ggandy_property_management,ggandy_property_telegram,ggandy_property_project \
  -i muk_web_theme --stop-after-init --no-http"
docker restart "$CONTAINER"

# 4. 確認模組狀態
docker exec "$DB_CONTAINER" sh -c "psql -U \"\$POSTGRES_USER\" -d $DB -c \"select name, state, latest_version from ir_module_module where name like 'ggandy%' or name like 'muk%' or name = 'base_automation' order by name\""
```

- 主題已安裝過、之後只是升級主題版本時，把 `-i muk_web_theme` 改成 `-u muk_web_theme`。
- LINE 房客 Bot：第一次上線時，升級完到「整合工具 → 設定」勾「LINE 房客 Bot」安裝；裝好之後，第 3 步的 `-u` 也要加上 `ggandy_line_bot`。
- 升級失敗時用備份還原：`pg_restore -U ... -d <新資料庫> --no-owner <dump 檔>`，filestore 解壓回 `/var/lib/odoo/filestore/<資料庫>`。

更多開發指令（Odoo shell、SQL、除錯方式）請看 [notebook/docs/dev_workflow.md](notebook/docs/dev_workflow.md)；資料模型與計算邏輯請看 [notebook/docs/architecture.md](notebook/docs/architecture.md)。

## 老闆可以怎麼看這套系統

這套系統的核心不是只記資料，而是把營運節奏自動化：

- 合約生效後，系統知道什麼時候該收房客租金。
- 租金到期時，系統自動建立房客帳單；逾期了自動提醒負責人。
- 房東匯款日到時，系統自動建立房東 Vendor Bill。
- 維修照片、維修與採購費用都能歸到物件與房間。
- 最後所有數字集中到 GGAndy 帳務總表；人在外面就用 Telegram 查。

老闆不用每次從房東合約、房客租約、發票、維修單裡一筆一筆對，可以先看總表掌握大方向，再往下追細節。
